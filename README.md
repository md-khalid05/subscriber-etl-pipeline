# CademyCode ETL & Data Update Pipeline

A Python-based ETL pipeline for cleaning and transforming the CademyCode dataset, with a Bash deployment script that promotes validated development artifacts to production.

The project demonstrates practical **ETL, data cleaning, logging, environment separation, version tracking, and Dev → Prod artifact promotion**.

## ETL Workflow

The project follows a simple development-to-production workflow:

```text
                    Source SQLite Database
                              │
                              ▼
                     Data Discovery
                              │
                              ▼
                    clean_pipeline.py
                              │
                    ┌─────────┴─────────┐
                    │                   │
                    ▼                   ▼
              Cleaned Data        Incomplete Data
                    │
                    ▼
              Development
                    │
              Version Check
                    │
              Manual Approval
                    │
                    ▼
                Production
```

### Python ETL Pipeline

The Python pipeline performs the main data-processing work:

1. Validate the source database.
2. Extract the source tables from SQLite.
3. Clean and transform student data.
4. Parse contact information.
5. Split mailing addresses into separate fields.
6. Convert numeric fields to appropriate types.
7. Segregate incomplete records for auditing.
8. Prepare reference tables.
9. Join student data with course and job reference data.
10. Write the cleaned dataset to SQLite.
11. Export a CSV copy.
12. Record execution details and metrics in the pipeline log.

# Running the Update Process

## Prerequisites

The project requires:

- Python 3
- Bash
- SQLite
- Project dependencies installed from `pyproject.toml`

If using `uv`, install the project dependencies with:

```bash
uv sync
```

If the project environment is already configured, activate/use the project's Python environment as appropriate.

---

## 1. Make the deployment script executable

From the project root:

```bash
chmod +x deploy.sh
```

---

## 2. Run the Bash update process

Execute:

```bash
./deploy.sh
```

You can also run it explicitly with Bash:

```bash
bash deploy.sh
```

---

# What `deploy.sh` Does

The Bash script coordinates the complete update process.

### Step 1 — Confirm the data-cleaning operation

The script asks for confirmation before running the ETL pipeline:

```text
Ready to clean the data? [y/N]:
```

Enter `y` or `Y` to continue.

---

### Step 2 — Run the Python ETL pipeline

The Bash script executes the development pipeline:

```text
dev/clean_pipeline.py
```

The pipeline generates the cleaned development artifacts and records execution information in the log.

---

### Step 3 — Check the changelog versions

The script reads the versions from:

```text
dev/changelog.md
prod/changelog.md
```

If both versions are identical, the deployment process stops because there is no detected version change.

If the versions differ, the script continues to the deployment confirmation.

---

### Step 4 — Approve production promotion

The script asks:

```text
Move dev artifacts to prod? [y/N]:
```

Enter `y` or `Y` to promote the generated artifacts.

---

### Step 5 — Promote production artifacts

The designated files are copied from `dev/` to `prod/`:

```text
dev/
├── cademy_cleaned.db
├── cademycode_cleansed.csv
└── changelog.md
        │
        ▼
prod/
├── cademy_cleaned.db
├── cademycode_cleansed.csv
└── changelog.md
```

---

# Bash Safety

The deployment script uses:

```bash
set -euo pipefail
```

This enables stricter Bash execution:

- `-e` — stop when a command fails.
- `-u` — treat unset variables as errors.
- `pipefail` — propagate failures from commands within a pipeline.

This helps prevent the deployment stage from continuing after an earlier command fails.

# Development and Production Separation

The project maintains separate `dev/` and `prod/` directories.

```text
Development
     │
     │  Build / clean / validate
     ▼
   dev/
     │
     │  Version check
     │
     │  Manual approval
     ▼
   prod/
```

This provides a simple environment-promotion model without directly modifying production artifacts during development.

# Project Goal

The objective of this project is to demonstrate the fundamentals of building a reliable batch ETL workflow rather than simply performing data manipulation with Pandas.

The project combines:

- **Python**
- **Pandas**
- **SQLite**
- **Bash**
- **Data validation**
- **Structured logging**
- **Environment separation**
- **Version tracking**
- **Artifact promotion**
- **Basic DataOps practices**

This project represents the initial ETL/DataOps stage of the learning progression. More advanced projects can extend these concepts using **Medallion Architecture, PySpark, Airflow, Docker, Databricks, cloud storage, and CI/CD**.
